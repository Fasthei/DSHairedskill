# 从残缺情报重建目标与交战规划

## 概述与何时用

真实交战里没有人会把架构图交给我们。能拿到的只是客户 kickoff 文档、公开仓库/招聘信息/DNS/云元数据，以及初期侦察的零散结果。本 skill 覆盖两件事：

1. **10.1** 如何把这些碎片拼成一张带置信度标注的目标架构图，并随交战推进持续修正；
2. **10.2** 如何在架构图上划出信任区、找出跨区提权路径，再用 RoE/时间预算把"理论上可行"收窄成"现在能打"，输出可交接的攻击情报简报。

适用信号：目标是含多 agent、orchestrator、向量数据库、MCP 工具层等组件的 AI 系统；情报不完整、需要边打边确认；需要给团队或客户一份"当前已知/假设/被阻断"的状态快照。

## 在 SOP 中的位置

对应 枚举→攻击→检测→规避 中"枚举"与"攻击规划"之间的桥接层：把被动/主动侦察（见 recon-ai-targets）产出的原始信号，转化为可指导后续攻击 skill（attack-single-agent、attack-a2a-multi-agent、attack-mcp、attack-rag-pipelines 等）选择打哪条路径的结构化决策依据。本 skill 不执行具体攻击动作，产出交给对应技法 skill 执行；执行结果再回填本 skill 维护的假设台账，形成闭环。

## 方法与技法（按小节）

### 10.1 从残缺情报重建目标

- **建立假设台账（assumption register）**：不要凭 kickoff 文档或 OSINT 直接下结论。每条观察拆成 `观察 → 假设 → 置信度 → 来源 → 验证状态` 五元组，验证状态只有 UNVALIDATED / VALIDATED / INVALIDATED 三态。置信度反映"来源可靠性"，不是"假设正确概率"——客户文档的高置信度描述仍需独立验证。
- **区分"未提及"与"已排除"**：文档没提到某项防护（如向量库鉴权），只能记为 LOW 置信度并标注"absence of evidence"，绝不能当作"该防护不存在"的确证；这类条目先驱动验证任务，不驱动攻击规划。
- **迭代更新架构图**：每轮新情报（端口扫描、API 响应、配置文件）都要回写台账，把假设提升为 VALIDATED、降级为 INVALIDATED，或新增条目；架构图本身可能不变，但对它的认知（因而威胁模型）会实质性改变——始终标注哪些组件是"已验证"哪些仍是"假设"。
- **按当前知识排序 crown jewel**：不要用最终架构做静态排名，而是"给定当前已知信息"排序资产的进攻价值，并随认知推进重新排序——早期看似边缘的资产可能在后期成为主目标。排序时区分"已可读取/已获取"与"仍需突破"两类，已可获取的资产应立即提取分析，而不是继续投入精力去"拿到访问权"。
- **映射 MITRE ATLAS 技术编号**：只对已确认组件和已验证访问级别做映射，标注每个技术"当前是否适用"及其前置条件（例如"若能读取模型注册表则适用""若能投递构造过的告警则适用"）；技术编号本身不进入执行计划，直到其前置假设被验证到足够置信度。用于连接后续攻击 skill 的技法选择。

### 10.2 信任区、提权路径与交战规划

- **识别信任边界的两种类型**：传统策略型边界（网关校验 token）之外，AI 系统引入"推理型"信任边界——某组件基于 LLM 推理结果（如告警分类）做出信任决策，没有策略背书。这类边界不能靠"绕过鉴权"打穿，而要靠输入操纵；识别时明确标注每条边界是"策略强制"还是"推理强制"。
- **构建信任边界表**：对每条 `From → To` 记录信任类型、强制机制、验证状态、进攻含义；未验证/仅从架构推断的边界要单独标注（如虚线），并说明它们仍代表"可能的攻击面"，规划时要区分"已验证攻击面"与"理论攻击面"，不能等同对待。
- **追踪跨信任区的提权路径**：先在无约束理论下画出效率最高的路径（例如"投毒某数据源 → 影响下游 agent 决策 → 触发带恶意参数的工具调用"),再逐段核对每一跳所需前提是否已验证。
- **用 RoE/时间预算做硬性过滤**：维护一张 go/no-go 决策矩阵——每条候选动作记录"已具备的信息""缺失的信息""验证所需时间成本""决策"。某些验证动作本身不可逆（例如触发一次工具调用即启动强制报告时钟），要在决策前明确标注这类代价，并优先选择"能解锁多条路径"且成本低的验证。没有时间验证完所有路径时，只能选风险/收益比更优的一条执行；两条都不可行时要回头重新审视架构图，找是否有遗漏的路径。
- **产出并维护攻击情报简报（attack intelligence brief）**：简报要包含目标概要、假设台账现状、范围/RoE 约束、当前优先路径与其 go/no-go 门槛、下一步行动清单;简报按版本迭代（每次重大验证结果都升版本号），版本历史本身就是决策日志——它记录的是"团队如何在不确定性下导航"，价值不低于最终交付物。简报的价值在于诚实反映"已知/假设/被阻断"，不是看起来完整。

### 10.3 技战法编排：攻击路径评分与情报增益（实战综合；非课程原文）

将候选路径拆成原子跳，每一跳标注 `前置状态 → 动作 → 预期状态 → 可观察证据 → 失败分支`。路径优先级不要只看最终影响，同时比较到达概率、情报增益、可组合性、成功/失败信号清晰度和时间成本。

优先执行“高情报增益、清晰可证、能解锁多条路径”的动作。每获得新证据，重新计算所有依赖该假设的路径，不只更新当前正在走的一条。

对同一现象保留竞争假设，例如高延迟可能来自模型路由、RAG、工具调用或队列；设计一次差分探针尽量同时区分多个解释。若一个动作只能证明组件存在，却不能改变攻击路径选择，应降低其优先级。

## 验证标准

- **工具/信息收集成功 ≠ 假设已验证**：拿到一份文档提到某组件，只把它记为 UNVALIDATED 假设；只有通过独立技术手段（端口探测、协议指纹、实际调用返回、日志核对等）复核后才能标记 VALIDATED。
- **假设已验证 ≠ 漏洞已确认存在**：即使确认了组件存在、连接方式属实，也只代表威胁模型某个节点被夯实，不代表该节点可被利用；是否可利用要交给对应攻击技法 skill 执行验证并给出独立证据。
- **推理型信任边界的确认需要展示"输入操纵改变了下游决策"**，仅凭"该边界看起来没有策略校验"不能算已确认，必须有实际输出变化作证据。
- **go 决策的前提是矩阵里列出的"缺失信息"已被处理**：没有走完决策矩阵、或跳过前置验证直接执行高代价/不可逆动作（如触发计费或报告时钟的调用），不算合规的交战规划产出。

## 常见失败与规避

- **把"文档没提到"当成"确认不存在"**：这是预交战威胁建模里最常见的错误（例如误判向量库无鉴权）。规避：未提及的项一律标 LOW 置信度 + absence-of-evidence，只派生验证任务，不派生攻击结论。
- **静态排序 crown jewel，不随认知更新**：会导致后期已证实的高价值资产被忽视。规避：每轮新证据后强制重新过一遍资产排序表。
- **把攻击规划当脚本执行**：以为验证完前置条件就该无脑执行整条链路。规避：把规划当决策树,每一步都留出"验证结果不符预期时如何转向"的分支（例如某个假设被推翻后要重新评估依赖它的所有路径）。
- **忽略不可逆验证动作的代价**：某些验证一旦执行会触发监控告警或强制报告窗口。规避：决策矩阵里显式标注每个验证动作是否不可逆、是否启动计时器，并据此排序执行顺序。
- **信任区划分只做一次就不再更新**：新情报到来后信任区边界可能改变（原本推断的边界被证实/推翻）。规避：信任边界表和架构图同步维护，边界状态与假设台账状态联动。

## 证据与报告

- 假设台账每条记录：观察原文/来源出处、派生假设、置信度、验证方法、验证状态、验证时间。
- 架构图快照：每次重大更新保留一版，标注哪些组件/边界为 VALIDATED、哪些为 UNVALIDATED/INFERRED,便于回溯"认知是何时变化的"。
- 信任边界表：完整记录 From→To、信任类型（策略/推理）、强制机制、验证状态、进攻含义、验证所用的具体证据（指纹结果、响应包、日志片段等）。
- go/no-go 决策矩阵：每个决策点的已知信息、缺失信息、验证成本、最终决策及理由,尤其是启动不可逆动作（计费/报告时钟）的时间戳。
- 攻击情报简报版本历史：每个版本对应的新增/失效假设、新增路径、被排除路径及原因,作为向客户或团队交接时"如何在不确定性下决策"的审计轨迹。
