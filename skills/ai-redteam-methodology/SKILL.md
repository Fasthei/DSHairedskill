## 概述与何时用

这是 DSHAIred 的“脑子”：不教具体技法（那是其余 11 个 skill 的事），只教两件事——

1. 一套贯穿全部 AI 红队工作的通用循环（枚举→攻击→检测→规避→确认），任何一次交战、甚至任何一个单点动作都可以放进这个循环里理解。
2. 一张路由表：看到什么样的目标/信号，该去加载哪个专项 skill。

在交战最开始加载我来定方向；交战中途卡住、不确定下一步该细化到哪个专项技法时，也可以回来加载我重新定位。

## SOP：五步循环

这五步不是一次性走完就结束的流水线，而是一个可以在任意粒度上重复的循环——可以是一次完整交战的顶层节奏，也可以是对单个漏洞点的一次局部验证。

1. **枚举（Enumerate）**：发现目标、与其交互以理解功能、画出它的工具/能力边界、确认它能访问什么。刻意去试探边界——问它不该讨论的话题。区分两种回应：**拒绝**（"我无权分享"）本身就确认了内容存在；**真阴性**（"我没有相关信息"）说明这条路径可能真的不通，或者信息确实不在其可及范围。枚举不完整时不要跳到攻击——先看 `recon-ai-targets`。
2. **攻击（朴素）（Attack, naive）**：先不做任何规避，用直接、明显的技术执行攻击。目的只有两个：确认这个攻击向量本身是否成立，以及观察它会触发什么日志/告警。这一步的产出是"向量是否可行"的原始信号，不是最终结论。
3. **检测（Detect）**：去看防御侧真正看到了什么——SIEM、日志、告警规则命中了没有、命中了哪一条规则、匹配到了什么特征。这一步直接决定了你下一步该规避什么，不能跳过靠猜。
4. **规避（Evade）**：针对第 3 步查明的具体检测点改造攻击，而不是泛泛地"更隐蔽一点"。每个防护措施都有可文档化的盲区：编码 payload 绕关键词过滤、隐藏文本绕内容扫描、描述性措辞绕祈使句检测等。规避的目标是明确的——绕过刚才确认的那条规则/那个信号,而不是绕过想象中的防御。
5. **确认（Confirm）**：再次检查检测面——没有告警不代表攻击成立，只代表规避对了那一条规则；同时必须回到目标端确认攻击本身仍然有效（工具是否真的执行了、数据是否真的落地、影响是否真的发生）。确认之后才闭环，进入下一轮枚举或下一个攻击向量。

**按需粒度**：这五步不是强制的固定轨道。一次性验证可以只做 1→2→5（枚举、朴素攻击、确认效果，不涉及规避）；已知会被检测的高价值目标可以直接从第 3 步开始（已经有检测规则情报）；单个动作（比如就试一条 payload）也可以只对应这五步里的一步。SOP 是地图，不是必须逐格踩过的轨道。

## 路由表：目标类型 → 加载哪个 skill

| 遇到的目标/信号 | 加载 |
|---|---|
| 还不知道目标是什么、需要先画攻击面/被动或主动侦察 | `recon-ai-targets` |
| 单个对话式 agent，需要直接/间接注入、记忆攻击 | `attack-single-agent` |
| 多个 agent 互相通信（A2A/编排/多智能体平台） | `attack-a2a-multi-agent` |
| 目标接了 RAG/向量库/检索增强 | `attack-rag-pipelines` |
| 目标暴露 embedding 接口或向量数据，想反推原文 | `embedding-inversion` |
| 目标通过 MCP 暴露工具/资源 | `attack-mcp` |
| 涉及代码执行、模型/数据篡改、供应链投毒 | `code-exec-and-tampering` |
| 目标跑在云/容器/编排环境，怀疑配置错误或逃逸 | `cloud-and-container` |
| 情报残缺，需要先重建目标拓扑再规划交战/提权路径 | `target-reconstruction-engagement` |
| 需要串联以上多章打一条完整攻击链（公网到域控级别） | `capstone-full-chain` |
| 需要先理解整体 AI 安全格局/威胁分类再决定往哪打 | `ai-security-landscape` |
| 不确定选哪个，或需要跨章总览 | 留在本 skill |

多数交战会依次经过好几个 skill：例如典型顺序是 `ai-security-landscape`（定位）→ `recon-ai-targets`（枚举）→ 按目标形态选 `attack-single-agent` / `attack-a2a-multi-agent` / `attack-rag-pipelines` / `attack-mcp` 等（攻击+检测+规避）→ 需要更深链路时并入 `code-exec-and-tampering` / `cloud-and-container` / `embedding-inversion` → 情报不全时穿插 `target-reconstruction-engagement` 重新规划 → 最终用 `capstone-full-chain` 的方式串成完整链条。这不是强制顺序,而是常见路径;实际交战按信号动态跳转。

## 贯穿纪律

无论走到哪个专项 skill、哪一步循环，以下纪律始终成立，任何专项技法都不能违反：

- **工具调用成功 ≠ 漏洞已验证**：请求返回 200、命令执行没报错、payload 被接受，这些只是"动作被执行"，不代表目标真的产生了预期的危害效果。必须回到目标端找到实际影响的证据（数据确实泄露了、权限确实被使用了、状态确实被改变了）才算验证。
- **拒绝 ≠ 确证，但拒绝也不是空**：模型说"我不能"往往说明它知道/能访问被问的内容，只是被策略挡住了——这是有信息量的信号，值得继续探；而"我没有相关信息"更可能是真阴性。两者都要记录,但不要把拒绝当成"此路不通"就放弃,也不要把它当成"已经拿到"。
- **证据关联**：每一个声称成立的发现，都必须能关联回原始证据——请求/响应记录、日志截图、SIEM 命中详情、目标端产生的实际产物。没有证据支撑的"应该是成立的"不能作为已验证发现写进报告，只能作为待验证假设。
- **假设要显式标注状态**：参考重建情报时的做法——未验证的假设、部分验证的假设、已验证的假设要分开标注，不能混为一谈；发现新证据推翻旧假设时要更新而不是悄悄忽略。
- **交战边界是硬约束**：只打确认已获用户授权的目标；规则里明确禁止的动作（如破坏性操作、生产环境写入）即便技术上可行也不能做。
