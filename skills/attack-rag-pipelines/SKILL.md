## 概述与何时用

RAG（Retrieval-Augmented Generation）系统在推理时从外部知识库动态检索上下文并注入到提示词中，而不是仅依赖模型训练时记住的知识。典型信号：应用自称"由 RAG/知识库驱动"、支持用户或管理员上传文档、回答里引用了明显是内部文档的内容（策略、hostname、账号）。

本 skill 覆盖：RAG 架构与其对应攻击面 → 从知识库窃取敏感信息 → 投毒/嵌入碰撞/检索劫持三类"写入侧"攻击 → 绕过输入/输出过滤与人工审查。适用于已确认目标使用 RAG（无论后端具体是何种向量库/搜索引擎）的红队评估。

## 在 SOP 中的位置

承接 [[recon-ai-targets]]里对 RAG 端点的被动/主动侦察结果：已知存在 `/query` 或类似接口、是否支持文档上传、是否暴露 MCP/工具能力。本 skill 是「枚举→攻击」阶段中针对 RAG 组件的攻击环节，产出的信息泄露/投毒结果可能进一步喂给 [[attack-single-agent]]（若 RAG 只是更大 agent 的一个组件）或 [[attack-mcp]]（若探测到 RAG 后端挂了可执行工具）。检测与规避技法（5.3）可与 [[attack-single-agent]] 里的注入规避技法互相印证、组合使用。

## 方法与技法（按小节）

### 1. 理解架构以定位攻击面

RAG 管道分两条流水线，各自都是攻击面：

- **摄取（ingestion）**：文档分块（chunking，注意分块重叠边界）→ 生成向量嵌入 → 写入三处存储：原始文本+元数据（关系库）、向量嵌入（向量库）、关键词索引（BM25 类搜索引擎）。三份存储互为镜像，是投毒类攻击的落点。
- **检索（retrieval）**：用户查询先过输入护栏（input guardrails，扫描注入/违规内容）→ 转成 embedding 做向量相似检索，同时并行做关键词检索（混合检索）→ 用元数据库做过滤/权限约束 → 对两路分数归一化并加权融合，取 top-K → 拼装成"增强提示词"（含检索上下文+用户问题）喂给 LLM → 输出可能再过一层输出护栏。

**可操作方法**：先用无害探测问题判断目标是纯向量检索还是混合检索（问措辞完全不同但语义相关 vs 用精确关键词命中的问题，对比召回差异）；判断是否有输入护栏（试探明显恶意措辞是否被拦）与输出护栏（试探是否对返回内容做正则/关键词脱敏过滤）——这决定后续该走"绕过输入侧"还是"绕过输出侧"。

### 2. 从知识库窃取敏感信息

两条泄露路径：探测 LLM 使其转述知识库内容；或直接打知识库/向量库/搜索引擎本身的弱鉴权。

**可操作技法**：
- 广泛枚举：直接问"列出所有 XX"（服务器名、AD 用户名、子域名/DNS 名称、VPN 配置、数据库连接串、服务账号密码、API Key）。RAG 后端 LLM 通常有非零 temperature，单次问法可能只召回部分结果——同一问题换措辞多问几次、并加"确保包含全部/all"这类强制完整性的措辞，观察召回数量是否增加。
- 一次性示例提示（one-shot prompting）：在问题里给出一个期望格式的例子（如给一个已知域名格式），引导模型按同样格式补全其余条目，比松散提问召回更精确、更完整。
- 隐蔽性收益：通过 RAG 接口做枚举，相当于把 PowerView/BloodHound/RID 猜测这类会产生本地进程与网络噪声的动作，替换成对一个"所有人都在用"的聊天端点的正常 HTTP/HTTPS 请求——本地不落地工具、流量与合法用户流量混在一起，且可能拿到你原本网络位置无法直达的隔离网段信息。
- 直接测试存储层弱鉴权：向量库/搜索引擎/元数据库若无独立鉴权或与前端权限不一致，可绕过 LLM 直接查询底层存储获取全量数据（而非受限于 top-K 检索）。
- 局限性要意识到：知识库内容可能过期，多次探测拼凑出的信息可能需要交叉验证；反复精细化提问会增加与系统交互的次数，存在被行为分析类检测发现的风险。


### 3. 投毒类攻击——针对用户 vs 针对模型

前提：能上传文档触发摄取（或等待常规摄取周期）。三种变体，目标不同：

- **摄取投毒（面向用户）**：上传的文档在未来被检索到并影响回答内容，目标是让处理该回答的人/工具上当（本质是钓鱼/社工，通常不直接导致代码执行，但一份文档可污染成百上千次后续查询）。要让攻击在评估时间窗口内命中，需先摸清知识库常被问到的高频主题（VPN、密码重置等），把恶意内容嵌入到贴合这些高频主题的文档里。
- **嵌入碰撞（面向用户，规模化）**：制作一份覆盖尽可能多主题（VPN、云服务、密码策略、软件安装……）的单一文档，在混合检索场景下同时利用语义相似（广泛主题覆盖）和关键词精确匹配（专业术语）两条路径提高被检索概率，从而让隐藏的恶意指令渗透进大量不相关查询的回答里。判断成功与否可用"在多次不同措辞查询下，恶意指令被包含进回答的比例"作为量化指标。
- **检索劫持 / 上下文注入（面向模型本身）**：与前两者相反，故意让文档只匹配少数你自己控制的、和知识库正常内容差异很大的查询——不追求高频碰撞，而是"只有自己知道的隐藏路径"，降低被自动系统/普通用户发现的概率。命中后触发模型在检索后执行嵌入指令。有效性依赖于先摸清 RAG 后端实际有什么能力（是否能读文件、发起网络请求、调用 MCP 工具等）——通过观察系统对"尝试执行命令/读取文件/发起请求"等探测的响应措辞（明确拒绝 vs 通用"没有该信息"/"undefined"）反推能力边界。


### 4. 绕过常见防御

先判断过滤器作用点——在生成前拦截输入 (input filter) 还是在生成后清洗输出 (output filter)，二者需要不同的绕过策略：

- **编码/替换绕过静态过滤**：若输出过滤是简单的字符串/正则匹配（如只查找 `@` 符号来脱敏邮箱），可通过替换指令（"把 @ 替换成 [at]"）在输出格式层面规避；若输入过滤扫描明显恶意措辞，可用零宽字符、Unicode 混淆等编码手段规避静态关键词/模式匹配。这类手段对自动化防护有效，但在人工复查监控日志（如可观测性平台）时仍非常显眼——只适合快速单次操作，不适合长期潜伏。
- **多模态伪装**：若目标支持图片 OCR 或类似多模态解析能力，把指令嵌入图片而非文本文档——模型仍能读取并执行，但人工审阅上传文件列表时只会看到一张"无害图片"。同理可用于 PDF 中的隐藏文字（白底白字）或元数据字段。
- **文档融合（document blending）**：把编码、替换、间接指令与"针对性投放"组合，并进一步在文件名、语气、风格、结构、元数据各个层面模仿知识库里已有的合法文档，使恶意文档在内容和形式上都与正常文档无法区分——这是比单纯编码更持久的隐蔽手段，可长期潜伏用于凭据钓鱼、信息收集或持久访问。
- **缓慢投毒（slow-drip poisoning）**：不一次性注入完整恶意指令，而是通过多次重新摄取，在数小时/数天/数周内通过多次微小修改逐步引入（底层原理类似"提示词分解/prompt decomposition"越狱思路：把受限请求拆成多个看似无害的片段）。若需要通过多次工具调用读取多个敏感文件，可考虑把操作分摊到多天（降低单位时间事件密度）或集中在一小时内做完再切回良性内容（降低被跨时间窗口关联的概率）——具体哪种更隐蔽取决于目标监控方案是基于事件密度还是基于长周期行为聚合。
- **事件疲劳（event fatigue）**：故意制造大量良性事件把真正的恶意变更淹没其中，既让人工分析师无法逐条核查，也可能让自动化扫描因积压而跳过部分检查——本质是利用防御方资源限制而非技术层面的绕过。


### 5. 收尾

本模块整体顺序应是：先摸清摄取/检索两条流水线的架构 → 定位攻击面 → 视目标是"读"还是"写"选择信息泄露或投毒/碰撞/劫持类攻击 → 若遇到过滤或人工审查，叠加编码/融合/慢速投毒等规避手段。三类写入攻击（摄取投毒/嵌入碰撞/检索劫持）互不排斥，可根据目标是要广撒网还是精准触发来选择或组合。

### 6. 技战法编排：先刻画检索函数，再设计投毒（实战综合；非课程原文）

把 RAG 当成可测量的排序系统，而不是只看最终回答。先用一组已知文档和成对查询刻画：

- **查询改写**：原始问题是否被扩写、拆分、翻译或加入历史上下文；比较原始查询与实际检索查询。
- **召回组成**：向量、关键词、图检索或结构化过滤各自贡献哪些结果，是否经过 reranker。
- **分块行为**：chunk 大小、重叠、标题继承、表格/代码块处理和跨页拼接方式。
- **排名稳定性**：同义改写、词序变化、语言切换和历史对话变化时，top-k 排名是否稳定。
- **上下文装配**：最终送入模型的片段顺序、截断位置、来源标签和引用信息是否与检索结果一致。

再按目标选择投毒方式：

| 目标 | 优先操纵点 | 主要指标 |
| --- | --- | --- |
| 广泛命中 | 多主题覆盖、关键词与语义双命中 | query coverage、top-k 占位率 |
| 精准触发 | 稀有短语、专用查询改写路径 | trigger precision、误触发率 |
| 压过权威文档 | 标题/元数据、重复片段、reranker 特征 | 平均排名、权威文档降位 |
| 跨 chunk 恢复 | 分块边界、重叠区、标题继承 | 片段拼接率、完整语义恢复率 |
| 引用伪装 | 来源标题、URL、作者、时间戳 | 错误引用率、来源归因偏移 |

使用**消融测试**确认真正有效的元素：从投毒文档中分别移除关键词、语义段落、标题、元数据、重复片段和指令部分；如果移除某元素后排名或行为不变，它不是攻击成功的关键因素。

### 7. 组合打法

- **查询改写劫持 → 检索占位 → 上下文注入**：先确认隐藏的改写词，再让投毒内容匹配改写后的查询而非用户原句，可显著提高精准触发率。
- **chunk 边界拆分 → 检索后拼接**：把单独看无害的片段放在相邻 chunk 或重叠区，验证装配阶段是否恢复完整语义；逐个片段查询用于排除单片段已经足够触发的情况。
- **元数据过滤操纵 → 权威来源伪装**：内容相关度不变，只改变部门、时间、文档类型、作者或标签，测量过滤器与 reranker 对元数据的实际权重。
- **多文档共识放大**：让多个独立文档表达同一错误结论，测试生成器是否把重复召回误当成多源佐证；必须确认这些文档是否实际来自同一摄取源或模板。
- **检索投毒 → 输出处理**：若恶意内容最终进入 Markdown、HTML、CSV、日志或工具参数，转 `attack-output-handling` 验证下游解释；RAG 命中率与下游副作用分别计算。

投毒效果至少报告四个数：`检索命中率、top-k 占位率、指令/错误内容采用率、良性查询误触发率`。只报告一次成功问答无法区分稳定攻击与模型偶然输出。

## 验证标准

- **工具/请求成功** ≠ **漏洞已验证**：模型返回了看似敏感的信息，不代表信息真实、当前有效、或确实来自越权访问——需核对返回内容是否对应真实存在的资产/凭据/配置（例如尝试用提取到的凭据实际登录、核实提取到的 hostname/IP 确实存在于目标环境）。
- 信息泄露类发现，验证标准是：能明确指出具体泄露了什么类别的敏感数据（凭据/内部拓扑/PII/密钥），且能重复复现（同一或等价查询多次可稳定获得），而非一次非确定性输出的偶然结果（RAG 后端 temperature 通常非零，需多次采样确认稳定性）。
- 投毒/碰撞类攻击的验证标准是：确认恶意内容确实完成了摄取（不是上传失败或被摄取过滤器拒绝），并有独立证据证明后续检索确实召回并触发了该内容（例如通过受控的多次查询统计命中率，而不是仅凭"文档已上传"就宣称攻击成立）。
- 检索劫持类攻击需验证模型确实执行了嵌入指令产生的实际效果（如确实读取并回显了目标文件内容），而不只是复述或"确认收到指令"。
- 规避类技法的验证标准是确认目标监控/过滤层确实未告警或未拦截（有条件时应与防御侧日志/看板做交叉确认），而不是仅凭主观"看起来没被发现"下结论。

## 常见失败与规避

- 高频问题拿不到完整数据：多为非确定性输出或问法不够精确，需要多次采样、换措辞、加"all/确保完整"等强制性措辞，或改用 one-shot 示例引导格式。
- 嵌入碰撞命中率低：文档主题覆盖不够广，或未同时兼顾语义相似与关键词精确匹配（混合检索环境下两者都要覆盖）。
- 编码/替换手段被人工复查发现：说明只做了自动化过滤绕过，未处理"内容/结构/元数据整体伪装"这一层，需升级到文档融合。
- 检索劫持一直不触发：可能目标 RAG 后端根本没有可执行的工具/文件读取能力，需先用无害探测确认能力边界，而不是假设能力存在直接构造利用。
- 慢速投毒被中途发现：多次重新摄取可能触发版本/变更审计告警，需评估目标是否对文档修改历史做审计，再决定投放节奏。

## 证据与报告

- 每次探测/攻击的原始请求与响应全文（含时间戳），尤其是触发泄露或执行的具体查询语句。
- 上传的恶意文档原始内容与摄取后从系统检索到的内容对比（证明确实被存入并可召回，而非仅上传成功）。
- 多次采样的命中率统计（用于碰撞/投毒类攻击的成立判定），而非单次截图。
- 用于反推系统能力边界的探测问答对（如"读文件被拒绝的具体措辞"），作为能力推断的依据链。
- 防御侧可获取时的告警/日志记录（证明规避是否真正生效），与攻击方视角的"看起来没被拦"分开标注。
- 所有敏感信息（凭据、密钥、PII）仅记录其存在与类别、脱敏摘录作为证据，不在报告中原样保留完整可用凭据。
