## 概述与何时用

**说明:本 skill 覆盖内容不在 OSAI 课程 66 小节范围内,是围绕课程 Ch3.3(间接提示注入,`OSAI/EN/Ch3`)的课程外扩展。** Computer-use / 多模态 agent 与纯文本 agent 的核心区别:它们把"看到的像素"或"听到的声音"当作又一条不可信输入通道,却往往像信任系统提示一样信任这条通道的解析结果——而人类审阅者审的是 UI 的视觉呈现,agent 审的是它自己对像素/音频的模型推断,两者可以被故意做得不一致。适用目标:浏览器自动化 agent(截屏后决定点击坐标或选择器)、桌面/RPA 自动化 agent、任何把图片/二维码/音频/视频字幕当输入源的多模态 agent。不适用于纯文本聊天接口(见 `attack-single-agent`)或 RAG 检索管线本身(见 `attack-rag-pipelines`)。

## 在 SOP 中的位置

延续 `attack-single-agent` 的枚举→攻击→检测→规避→确认五步法,但把"投毒的数据源"换成视觉/听觉媒介,把"agent 的决策"换成"点击坐标/按钮选择/跨应用操作"。与间接注入(3.3)同源:载荷不进聊天框,而是预先埋入 agent 将要"看到"或"听到"的素材里,在 agent 执行感知→决策循环时触发。

## 方法与技法(按载体分类)

- **视觉诱导点击 / clickjacking 变种**:利用 computer-use agent"截屏→视觉定位可点击元素→按坐标或视觉特征点击"的机制,构造与真实功能按钮视觉相似但实际触发不同操作的界面元素(如把"取消"位置渲染成视觉上像"确认/继续"的按钮,或用透明/层叠元素覆盖在合法按钮上)。触发条件:agent 依赖视觉识别而非可信的 DOM/accessibility 树校验来判断"这是不是我要点的按钮"。
- **DOM 与页面视觉渲染不一致**:让页面对人类审阅者(读 HTML 源码/文本快照)呈现一套内容,对截屏/渲染引擎呈现另一套(例如用 CSS 定位、iframe 叠加、Canvas 绘制文字而非真实 DOM 文本)。若 agent 的"内容扫描/安全检查"环节读取的是 DOM/文本序列化而实际决策依据的是截屏视觉,两者不一致即可绕过检查后仍诱导视觉驱动的操作;反过来,若 agent 只信 DOM 不截屏比对,也可以反向利用。触发条件:agent 的检测面与决策面使用了不同的页面表征。
- **图片中的指令注入**:在 agent 会截屏或上传处理的图片里嵌入视觉可辨(或对人类不易察觉、对 OCR/视觉模型高辨识度)的文字/图案,构造成"系统提示""操作说明""授权码"等诱导性内容,利用 agent 把图片 OCR/描述结果当作可执行指令合并进上下文的行为。可类比 3.3 的"视觉隐藏绕过内容扫描器",区别在载体从网页 CSS 隐藏文本换成图片像素本身。
- **二维码中的指令注入**:二维码解码后得到的文本对人类不可读(除非专门扫描),但会被 agent 当作普通字符串处理甚至直接作为指令跟随。适合藏在"看起来无害"的场景截图、文档插图、或页面装饰性元素中,人工审阅只看到一个方块图案,不会意识到内容。
- **音频指令注入(包括超声/低可闻段)**:在 agent 处理的音频流(语音助手输入、会议录音摘要、视频音轨)中混入人耳不易察觉或语义上被忽略、但语音识别模型会转写出来的指令片段,使 ASR 转写结果里混入"指令性文本"并被下游 LLM 当作用户/系统意图处理。触发条件:agent 把 ASR 输出直接拼入决策上下文,未做"这是不是真的用户在说话"的来源校验。
- **视频字幕/时间轴中的指令注入**:预置或实时生成的字幕文件(srt/vtt)或视频内嵌文字条目里插入指令性语句,利用 agent 处理视频摘要/审阅任务时把字幕文本视为可信文字内容合并进上下文。
- **延迟出现的页面指令(time-delayed injection)**:页面初次渲染/agent 首次截屏时内容正常,经过若干秒或某个交互后才通过 JS 动态注入/替换出诱导内容,利用 agent"先截一次屏做安全判断,后续操作复用同一份判断结果不复核"的时间差。触发条件:agent 的检测发生在 T0,但真正执行操作在 T0 之后的某个时刻,且中间没有重新校验。
- **伪授权/系统弹窗界面**:构造视觉上高度仿真的操作系统级或应用级弹窗(权限请求、"验证您是人类"、"检测到风险需重新授权"等),诱导 agent 在没有真实权限提升发生的情况下,把弹窗上的按钮当作合法系统交互点击并执行(例如"允许"实际触发下载/执行外部脚本)。触发条件:agent 无法区分"操作系统真实弹窗"与"页面内用 HTML/Canvas 绘制的仿真弹窗"。
- **跨应用敏感信息搬运**:利用 computer-use agent 可以在多个应用/窗口间来回操作的能力,诱导其把一个应用(如内部工单系统、密码管理器界面)中截屏看到的敏感信息,复制/转录/粘贴到另一个受攻击者控制或可外泄的应用/表单里,完成"agent 亲自动手"的数据搬运而非直接工具调用外泄。触发条件:agent 具备跨窗口/跨应用操作能力且没有对"信息来源应用的敏感级别"做区分策略。

**测试件生成工具:`multimodal_payload_gen`**——用于按上述任一类别生成测试用的图片/二维码/音频/字幕载荷文件(嵌入指定的诱导文本/指令片段),供离线检视载荷本身是否符合"视觉/听觉可被目标模态解析出指令语义"这一前提。**该工具只生成载荷文件,不投放；把生成的载荷实际投喂给正在运行的真实 computer-use agent 并观察其执行,属于 P4(需用户已授权的真实靶场),不在开发/演示阶段进行。**

### 技战法编排：四表示、三时刻、两条决策通道

对每个测试页面或媒体同时保存四种表示：**源内容**（HTML/字幕/元数据）、**结构表示**（DOM/accessibility tree）、**感知表示**（截屏/音频波形）和**模型解释**（OCR/ASR/视觉描述）。攻击成立的位置，通常正是四者第一次出现语义分叉的位置。

按三个时刻重放同一任务：

1. **T0 检查前**：记录页面初始内容及 agent 的目标理解。
2. **T1 决策时**：记录用于选择按钮、坐标、文本框或应用窗口的实际感知输入。
3. **T2 动作后**：记录页面变化、焦点变化、跨应用数据流和下一轮感知输入。

再区分两条决策通道：agent 是依据**语义通道**（DOM、accessibility、OCR 文本）行动，还是依据**像素通道**（截图坐标、图标相似度）行动。用成对测试件只改变其中一条通道：

- DOM 文本不变、只改变视觉位置或覆盖关系，测试像素通道。
- 视觉外观不变、只改变 accessibility 名称或隐藏文本，测试语义通道。
- 两条通道给出冲突指令，观察 agent 的优先级和冲突消解策略。

### 递进打法

- **感知探针**：先让媒体只携带唯一标记，确认 OCR/ASR/二维码/视觉模型能稳定解析。
- **指令归因探针**：让标记与页面正常任务发生轻微冲突，观察 agent 是引用页面内容、用户任务还是历史状态作为行动理由。
- **动作选择探针**：提供两个都可完成表面任务但副作用不同的候选动作，测量诱导内容能否稳定改变选择。
- **跨步保持**：在下一次截屏或下一应用中移除诱导内容，观察其影响是否仍保留在计划、记忆或待办队列里。
- **跨模态拼接**：把完整意图拆到图片、字幕、二维码或页面文本的多个载体中，验证 agent 是否在内部汇总后恢复了整体语义；逐个移除载体做消融测试，确认哪一部分真正贡献了行为变化。

每类实验至少包含：无载荷基线、视觉/语义等价的良性对照、目标载荷和一个消融变体。只有目标载荷相对三组对照稳定改变行为，才能把结果归因到具体多模态技法，而不是模型随机性或页面本身的可用性问题。

## 验证标准

严格区分三层,报告中必须标注处于哪一层(与 `attack-single-agent` 一致的纪律):

1. **载荷已生成**:`multimodal_payload_gen` 产出了图片/二维码/音频/字幕文件,人工或独立工具复核确认载荷中确实携带了预期的诱导文本/指令语义(如 OCR 复跑能读出、二维码能被标准解码器解出、ASR 能转写出、字幕文件语法正确)。这只证明"载荷做出来了",不证明任何 agent 会被它影响。
2. **目标端确被诱导执行**:载荷被投喂给真实运行中的 computer-use/多模态 agent(P4,已授权靶场),且能证明 agent 的后续行为(点击了哪个坐标/触发了哪个工具调用/搬运了哪些数据)确实源自载荷中的诱导内容,而非任务本身的正常逻辑——需要有 agent 决策日志、截屏序列、执行前后状态对比等佐证,而不是"看起来它照做了"。
3. **发现已验证**:在 2 的基础上,完整走完枚举→攻击→检测→规避→确认,并说明目标 agent 有无任何"来源校验/二次确认/权限提示"机制被绕过,以及绕过依据的具体机制假设(视觉与 DOM 不一致、时间差、跨模态信任传递等)是否被实际证据支持。

只有第 3 层可称为"已验证漏洞";第 1 层严禁在报告中升级表述为"发现"或"漏洞"。

## 常见失败与规避

- **载荷对人类审阅明显可疑(如二维码突兀地出现在无关截图里)** → 结合场景做视觉/语境融合(嵌入到看似正常的装饰、水印、背景元素位置),但仍需在报告中如实记录载荷的可疑程度,不夸大隐蔽性。
- **agent 对截屏做了 DOM/accessibility 树交叉校验** → 该类攻击面对此类 agent 不成立,应先确认目标是否真的仅依赖纯视觉决策,再决定是否继续该向量,而不是假设所有 computer-use agent 都同等脆弱。
- **ASR/OCR 引擎本身对指令性短语有内容过滤** → 参考 3.2/3.3 的编码与措辞规避(改写为描述性语气、拆分片段),但同样需要目标端确认才能称为"规避成功"。
- **延迟注入依赖的时间窗口不存在(agent 每步都重新截屏复核)** → 该向量不成立,不要凭理论假设直接判定漏洞存在。

## 证据与报告

- 载荷文件本身及生成参数(`multimodal_payload_gen` 的输入配置),供复现载荷生成过程。
- 载荷语义复核记录:OCR/ASR/二维码解码器对载荷的独立解析结果,证明载荷确实携带预期指令语义(层级 1 证据)。
- P4 阶段:目标 agent 的完整截屏序列/决策日志/工具调用记录,标注触发投放的时间点与之后的行为变化(层级 2、3 证据)。
- 是否存在 DOM/视觉不一致、时间差、跨模态信任传递等具体机制的独立验证记录(如同时保存 DOM 快照与截屏对比)。
- 明确标注该测试是在已获授权的用户靶场(P4)完成,还是仅停留在载荷生成/离线检视阶段;禁止将离线生成的载荷样例包装成"已在目标环境验证"的结论。
