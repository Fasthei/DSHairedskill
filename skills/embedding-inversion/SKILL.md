# Embedding Inversion（嵌入反演攻击）

## 概述与何时用

覆盖对向量数据库/RAG 系统中嵌入向量的攻击：从原始向量恢复人类可读文本、判断特定敏感值是否存在、或推断文档的高层属性。适用场景：红队已拿到目标向量库的 embedding 导出（或具备读取向量的接口访问），需要评估/执行嵌入反演以恢复凭据、密钥或其他敏感信息。

一个核心误区要先破除："嵌入是为了保留语义而设计的不透明数字，看起来无法逆向"——恰恰因为语义被保留，信息才可被恢复。这个误区本身就是可利用的攻击面认知。

三类攻击目标：
- **Embedding Inversion**：从向量重建原文，收益最大但对资源/知识要求最高。
- **Membership Inference**：只回答是否存在某具体值（如某密码/API key 是否在库中），成本低，可与反演结合大幅增强效果。
- **Attribute Inference**：不还原全文，只推断文档高层元数据（敏感度、分类），用于从海量 chunk 中快速分诊出高价值目标。

## 在 SOP 中的位置

对应"枚举→攻击→检测→规避"中的 **攻击（数据泄露类）** 环节，前提是已完成对目标 RAG/向量库的访问侦察（可与 `attack-rag-pipelines`、`recon-ai-targets` 衔接：先用 RAG 攻击面枚举拿到向量导出权限，再用本 skill 做向量层面的深度利用）。内部顺序：理论判断可行性 → 侦察确定模型与压缩情况 → 分诊定位高价值 chunk → 反演恢复文本 → membership inference 填充高熵值。

## 方法与技法（按小节）

### 6.1 攻击可行性判断（理论）

先判断走哪条路，而不是上来就跑工具。四类反演方法按投入递增：Zero-Shot（无需训练，需知道嵌入模型）→ Few-Shot（有少量泄露/注入的明文-向量对，可不知道模型）→ Supervised（预训练解码器，需模型访问/权重）→ Surrogate（代理攻击，模型未知时的兜底）。选择依据：时间窗口、可用资源（本地 LLM/GPU、词表、模板库）、对目标系统的已知信息。

关键限制因素（决定"能不能打”，不是"工具跑没跑成"）：
- **高熵 token**：密码、API key、hash 这类随机字符串没有语义可预测性，语义反演（LLM/解码器）天然搞不定，必须转成 membership inference 逐候选比对。
- **模型识别**：多数方法需要先知道用的是哪个嵌入模型；只有 surrogate 和有泄露对的 few-shot 可以绕过这一前提。
- **降维/量化**：生产库常用 PCA/random projection 降维或标量/乘积量化压缩存储，这会丢失可反演的信息量——评估前先确认向量是否为原始维度还是压缩形式，直接决定可行性上限。
- **领域不匹配**：监督式解码器/校正器在特定语料（如 MSMARCO）上训练，目标是法律/医疗/内部文档等异域文本时效果显著下降。


### 6.2 侦察：确定模型、维度、高价值目标

**确定嵌入模型**：优先查向量库自身的 schema/配置（很多向量库在摄取时自行计算 embedding，配置文件/环境变量会暴露模型名）；其次用维度指纹法——`len(vector)` 得到的维度数对常见模型有一定指示性（如 384 常见于 MiniLM 系、1536 常见于 OpenAI ada-002/3-small、3072 对应 3-large、1024 对应 Cohere v3、768 对应 BGE-base），但多模型共享同一维度，只能作为初筛，需结合文档/OSINT/社会工程进一步收窄。

**分诊（Chunk Triage）**：生产库常有数千至数万 chunk，逐个反演不现实。核心思路是在向量空间内直接判断语义类别，不需要先反演——用一组"敏感度探针"（凭据、API key、SSH key、PII、财务数据、基础设施密钥等类别的短文本）分别嵌入，计算每个 chunk 与各探针的余弦相似度，命中高分即为高价值目标。可用级联多阶段打分（如密度/主题孤立度 → 探针相关性 → 试探性重建相似度）做 Reciprocal Rank Fusion，把候选从全库收窄到几个目标，几秒内完成。看分数分布的自然断层（如 top-3 明显高于第 4 名）作为截断依据。


### 6.3 零样本嵌入反演（无需预训练）

已知嵌入模型、拿到目标向量、且已分诊出高价值 chunk 后使用。两条路径：

**模板库 + Membership Inference**：把反演拆成两步。第一步恢复语义结构/句式（保留上下文，把高熵值替换成占位符如 `{PASSWORD}`、`{URL}`）；第二步对每个占位槽用词表逐候选嵌入、比对与目标向量的余弦相似度，最高分即为该槽真实值。为提高可靠性：自动检测目标领域并生成大规模、结构多样的模板库（而非几十条手写模板）；用相对阈值自适应筛选参与投票的模板（而非固定 top-N），并做多样性去重防止近似重复模板虚增一致性；多模板"投票"取共识而非单模板判定，配合加权共识（相似度越高权重越大）和差距置信度（胜出候选领先第二名的margin）。已知的目标域上下文信息（如目标公司名/域名）可作为参数注入模板，提高信噪比。

**Beam-Search 直接重建**：模板库覆盖不到目标领域/句式时使用。核心算法思路：用一个通用语言模型逐 token 提出候选延伸，每个候选延伸嵌入后与目标向量算相似度，保留最优若干条 beam，迭代若干步（典型 30-40 步）直至收敛到"可读且嵌入接近目标"的文本。重建结果是近似的——能捕捉语义结构，但高熵值仍是乱码；需叠加基于信息熵与格式正则（识别 `sk-`、JWT 前缀、hex hash、混合字符密码等模式）的高熵区域自动检测，把检测到的区域转成带类型的占位槽，再套用 membership inference 填值。此路径计算开销显著更高（需要额外加载生成模型+海量嵌入调用），GPU 基本是硬需求；模板库已能覆盖目标领域时不必用这条更贵的路径。

决策顺序：先试模板库方法（无 GPU、分钟级）；相似度或置信度不足（低于强/中等阈值）再上 beam-search；两者互补而非替代。


### 6.4 预训练嵌入反演（投入训练成本换取更强能力）

上述方法都在推理时现算，预训练方法反过来：提前训练一个"从向量到文本"的映射模型，换取更快的单条推理速度、以及在嵌入模型未知/需要批量攻击同模型大量向量时的能力。

**编码器-校正器架构（Vec2Text 思路）**：一个 inverter 从目标向量生成初始文本假设，一个 corrector 反复根据"目标向量与当前假设向量的残差"迭代精修假设，多轮（典型 20-50 轮）后收敛。原始研究只对少数公开嵌入模型有现成权重；针对未覆盖的目标模型，需要自建训练语料（企业场景可用合成文本+少量通用语料混合）、自行训练 inverter 与 corrector——这是显著的前期投入（数十小时级 GPU 训练），只有在有充分准备时间、且需要对同一嵌入模型反复作战时才划算。

**代理对齐路径（无需知道目标模型时）**：向目标可写入的向量库注入一批"金丝雀"文档（canary），用目标系统自己的嵌入过程为这些已知明文生成向量，从而学出一个从目标嵌入空间到文本的映射，绕开"必须先识别模型"的前提。这条路径需要目标可写权限，且注入规模与隐蔽性要权衡（更少的金丝雀数量在可接受质量损失下能显著降低可观测的写入痕迹，适合隐蔽约束下的交战）。

**推断探测放大反演结果**：单靠上述神经解码器直接输出的文本通常是"语义方向对，措辞不准"的近似结果，但已足以提取关键词/领域片段。把这些片段作为查询词，通过目标 RAG 系统自身的问答/检索接口发起针对性提问，往往能直接检索出原文内容。这里有一个重要的规避视角：**即便输出侧有护栏会脱敏具体敏感值（如把密码替换成占位符），脱敏标记本身就暴露了槽位存在**，从而给 membership inference 提供了现成的攻击入口——护栏挡住了"直接输出"，挡不住"槽位存在性+候选枚举"。

选择依据：模型已知、无需批量复用 → 优先零样本方法；模型未知或需要对同一模型批量攻击、且有充分准备时间 → 预训练/代理对齐路径更划算。


### 6.5 技战法编排：先做空间指纹，再选反演器（实战综合；非课程原文）

在反演前先建立 embedding 空间指纹：用已知短文本、长文本、多语言、数字串、结构化标识符和随机文本生成参考向量，比较维度、范数、零值比例和余弦分布；对同一文本重复编码判断确定性；对大小写、空格、标点、Unicode 归一化和截断边界做差分，推断预处理。

按目标选择攻击器：

| 目标 | 首选方法 | 主要评价 |
| --- | --- | --- |
| 有限候选中的密钥、账号、主机名 | 候选生成 + 最近邻排序 | top-k 命中、真实候选排名 |
| 固定模板中的缺失字段 | 模板枚举 + 分字段搜索 | 字段准确率、查询规模 |
| 自由文本语义恢复 | 预训练解码器/生成器 | 语义相似、实体恢复率 |
| 判断候选是否存在 | 相似度校准的成员推断 | ROC-AUC、TPR@低 FPR |

不要只返回“最相似候选”。先用已知正负样本校准相似度分布，再报告目标候选的绝对相似度、相对间隔以及在负样本中的分位数；第一名与第二名接近时标记为歧义结果。

组合顺序使用“粗筛 → 局部扩展 → 结构约束 → 独立验证”：先找语义邻域，再围绕高分候选扩展大小写、分隔符、数字后缀和字段组合，最后用格式、校验位或目标系统已知事实验证。只能恢复主题时应归类为语义泄露，而不是精确原文恢复。

## 验证标准

必须区分三个层级，不能互相替代：
1. **工具调用成功**：脚本跑完、返回了某个候选值/相似度分数。这只说明流程执行完毕，不代表结果正确。
2. **统计置信充分**：多模板/多候选投票的共识强度（如 N/M 模板一致、胜出候选与次优候选的 margin、置信度标签是 Strong/Moderate 而非 Weak/Unlikely）达到可信阈值。
3. **发现已验证**：拿到 ground truth 佐证（如原始文档、系统日志、独立信道确认）实际比对候选值与真实值一致，或者候选值在目标系统上被成功用于认证/访问验证。

只有第 3 层才能写成"已验证发现"；第 1、2 层只能写成"候选/待验证"，并在报告中注明置信度依据。低置信度结果（Weak/Unlikely）不得当作确认结论上报，应继续用 beam-search 或代理对齐等更强方法交叉验证，或明确标注为未确认。

## 常见失败与规避

- **高熵值反演失败**：症状是语义结构对但具体值乱码/明显不对。规避：不强行用语义方法猜高熵值，转成"结构反演 + membership inference 枚举候选词表"两阶段。
- **模板库覆盖不到目标领域**：单模板/小模板库产生的相似度普遍偏低、无法形成明显 margin。规避：先做自动领域识别再生成大规模领域特化模板；仍不行则换 beam-search 直接从向量重建结构。
- **朴素"取最高相似度"导致假阳性**：当候选词与目标机构名/领域词高度相关但并非真实值时（如误判包含机构名的候选），单一分数会被上下文词干扰。规避：分离出高熵槽位本身的贡献，用多样化模板的共识而非单模板单分数判定。
- **降维/量化后反演效果差**：目标向量库对存储做了压缩，导致语义信息本身已丢失，任何方法都很难恢复。规避：侦察阶段先确认存储是否为原始维度，评估前明确告知可行性上限，避免过度投入训练资源。
- **护栏掩盖具体值但暴露存在性**：输出脱敏产生的占位符本身是信息泄露信号。规避：把脱敏标记转成待填充槽位，走 membership inference 补全，而不是止步于"护栏挡住了"的错误结论。
- **过度依赖单一工具当作即插即用方案**：课程原型工具是概念验证，针对具体目标域的参数、模板、阈值需要现场调整，不能假设默认参数直接适用于任意生产系统。

## 证据与报告

上报每一项候选发现时需附带：
- 原始导出的向量数据来源与访问方式（如何拿到导出权限、访问时间点）。
- 使用的嵌入模型识别依据（配置来源/维度指纹/OSINT，明确置信度而非断言）。
- 分诊阶段的打分依据（触发的探针类别、分数与截断依据）。
- 反演阶段的具体输出：相似度分数、投票/共识明细（多少模板/beam 支持该结果）、置信度标签。
- 最终候选值与 ground truth 的比对结果（如有），或明确标注"未独立验证"。
- 使用的方法路径（零样本模板法 / beam-search / 预训练解码器 / 代理对齐）及为何选择该路径，便于复现与追溯升级路径。
