# Model Privacy & Black-Box Extraction Attacks（黑盒模型隐私与提取攻击）

**范围声明：本 skill 内容不来自主体资料库，是 DSHairedskill 的课程外扩展。** 课程内唯一相邻内容是嵌入反演（`embedding-inversion` skill），覆盖的是"已拿到向量本身"之后的反演；本 skill 覆盖的是"只有查询接口、没有向量/权重"的更前置场景（模型提取、训练数据提取、成员推断、属性推断、侧信道、对抗样本、决策边界探测、能量-延迟攻击），两者可衔接但不重叠：先用本 skill 从查询接口窃取代理模型或推断成员资格/训练数据，再视是否拿到 embedding 导出决定要不要转 `embedding-inversion`。内容依据 NIST AI 100-2（*Adversarial Machine Learning: A Taxonomy and Terminology*，evasion/privacy 分类）、MITRE ATLAS（ML Attack Staging、Exfiltration via ML Inference API 等战术）、OWASP（ML Security Top 10 / LLM Top 10 中的 Model Theft、Training Data Extraction 相关条目）整理蒸馏，不整段复制来源文档。

## 概述与何时用

覆盖对象：只暴露推理查询接口（HTTP API、SDK、UI 输入框）的黑盒模型——传统 ML 分类器/回归器、embedding 服务、也包括黑盒 LLM API。攻击者不掌握权重、梯度、架构细节，能力边界完全由"能发多少次查询、每次查询能拿到多少信息（top-1 标签 / 完整概率分布 / logprobs / 仅排序 / 无输出只有延迟）"决定。

面对以下信号时加载本 skill：
- 目标只给一个推理端点，需要评估"能不能把这个模型偷回来"（模型提取/蒸馏）。
- 需要判断"某条具体样本是否在训练集里"（成员推断）或"训练集里是否包含某类敏感群体/属性"（属性推断、训练数据提取）。
- 目标 API 返回的信息比预期丰富（完整概率分布、置信度、排序、甚至响应时间/资源消耗有可观测差异），需要判断这些"多余信息"能不能被武器化成侧信道。
- 需要用对抗样本探测模型决策边界，评估鲁棒性或构造规避载荷（对接 `recon-ai-targets`/规避类 skill 时的底层技法来源）。

## 在 SOP 中的位置

对应"枚举→攻击→检测→规避"中的**攻击（模型窃取与隐私泄露类）**环节。典型顺序：

1. 侦察阶段（可与 `recon-ai-targets` 衔接）先确定：查询预算/限流、返回信息粒度（标签/概率/logprobs/仅排序）、是否可观测延迟或资源占用——这三项直接决定下面哪些技法可行。
2. 模型提取/蒸馏：用查询-响应对训练代理模型，作为后续离线攻击（白盒对抗样本生成、进一步隐私攻击）的跳板。
3. 隐私类攻击（成员推断、属性推断、训练数据提取）可独立于提取进行，也可在拿到代理模型后离线增强（有本地代理模型时置信度/攻击效果通常显著提升）。
4. 侧信道（概率/排序/时间/能量）贯穿全程，是"接口暴露了多少"这个前提问题的答案来源，决定上面几类攻击的上限。
5. 对抗样本与决策边界探测既是独立攻击目标（规避检测/分类器误导），也是给隐私攻击提供额外查询信号的手段。
6. 若目标暴露的是向量库/embedding 而非纯推理 API，转 `embedding-inversion`；若目标是训练/部署管线而非黑盒接口本身，转 `code-exec-and-tampering` 或 `attack-mcp`。

## 方法与技法（按小节）

### A. 前提判断：资源、查询预算、输出粒度

黑盒攻击的可行性首先由三个前提变量决定，而不是由"想不想打"决定：

- **查询预算**：是否有限流/计费/告警？免费/宽松预算下可跑数万至数十万次查询做高保真提取；强限流下只能做低查询量的启发式攻击（如仅用少量样本做粗粒度成员推断，或牺牲提取精度换查询数）。
- **输出粒度**（决定性因素）：
  - 完整概率分布/logprobs 可用 → 高保真模型提取（可训练功能等价甚至参数级近似的代理模型）、高置信度成员推断（基于损失/置信度阈值）、更精细的属性推断。
  - 只有 top-1 标签/排序无分数 → 提取质量大幅下降，只能做基于标签的提取（label-only extraction）和基于决策边界距离的成员推断（需要额外的对抗扰动查询来估计边界距离，查询代价更高）。
  - 无结构化输出、只有原始文本（LLM 场景）→ 需要先做输出解析/概率代理（如让模型输出置信度自评、或用多次采样估计经验分布），可靠性明显低于直接拿 logprobs。
- **是否可观测非功能信号**：响应延迟、错误信息细节、速率限制触发点、（若可物理接触或托管在可测环境）能耗/电磁/时序特征。这些信号独立于输出内容之外，往往是防御方没有意识到会泄露信息的通道。

判断顺序：先确认预算和粒度，再选具体技法；粒度不足时优先考虑"降级到 label-only 变体"而不是放弃，同时如实告知可行性上限会明显低于满粒度场景。

### B. 模型提取 / 代理模型蒸馏（Model Extraction / Surrogate Distillation）

目标：用查询-响应对训练一个功能近似（有时参数级近似）的本地模型，用于离线攻击、绕过限流、或规避检测（本地测试无痕迹）。

- **查询策略**：均匀随机采样输入空间效率低，优先用主动学习式策略——从种子样本出发，优先查询模型"不确定"的区域（概率分布接近均匀、或落在已知决策边界附近的样本），用更少查询获得更高保真度。对分类任务，可先用公开同分布数据集或合成数据打底，再用主动学习细化边界附近样本。
- **蒸馏训练**：用完整概率分布做软标签蒸馏（保留更多决策边界信息）优于只用 top-1 硬标签；LLM 场景对应"用目标模型的输出（含 logprobs 时更好）训练/微调一个开源基座模型"，即课程外常说的"model distillation via API"路径。
- **参数级提取**（更进阶，通常仅对简单模型如线性/浅层网络可行）：利用查询-响应对解方程组式地反推权重，需要大量结构化查询（如沿特定方向的微小扰动查询）且对模型架构有一定先验假设，对深层网络/LLM 一般不现实，实操中以功能等价提取为主。
- **产出用途**：代理模型可用于——(a) 离线生成白盒对抗样本再搬到黑盒目标上做迁移攻击（transferability），比纯黑盒查询高效得多；(b) 离线跑成员推断/属性推断，减少对目标接口的查询次数和可疑行为暴露。

### C. 训练数据提取（Training Data Extraction）

目标：让模型直接吐出训练集中的原始片段（记忆化内容），常见于大模型对稀有/高重复样本的记忆。

- **触发记忆的提示策略**：用训练数据中常见的前缀/模板（如已知格式的文档开头、代码文件头、邮件模板）引导模型续写，观察续写是否与已知/可验证的真实数据高度吻合；对重复出现于训练集的样本（重复次数越高，被记忆概率越大）成功率显著更高。
- **与成员推断结合**：先用成员推断筛出"疑似被记忆"的候选前缀，再针对性做提取式提示，比盲目枚举提示更省查询预算。
- **验证要求**：模型吐出的文本"看起来像敏感数据"不等于确实是训练数据——必须能独立比对到真实数据源（公开数据集、已知文档、用户提供的 ground truth）才算验证成立，否则只是"模型生成了看似真实的内容"（LLM 幻觉与真实记忆在黑盒条件下表面特征相似，容易误判）。

### D. 成员推断攻击（Membership Inference, 非向量场景）

与 `embedding-inversion` 中"比对候选值与目标向量余弦相似度"的向量层面 membership inference 不同，这里是对分类器/生成模型本身的查询层面攻击：判断某条具体样本是否参与过训练。

- **基于置信度/损失的攻击**：训练集样本上模型通常表现出更高置信度或更低损失（过拟合的直接症状）。构造影子模型（shadow model，用与目标同分布但已知 train/non-train 划分的数据训练，模拟目标行为）学习"置信度分布→成员/非成员"的判别边界，再把目标样本的真实查询响应代入该判别器。
- **label-only 变体**：目标只给标签时，用对抗扰动估计该样本到决策边界的距离——训练集样本通常离边界更远（需要更大扰动才能翻转预测），以此作为成员信号，代价是需要多次扰动查询单个样本。
- **典型误用场景**：判断某条 PII 记录、某个受版权保护的文档、某条医疗/金融记录是否被用于训练模型（合规与隐私评估的核心问题之一）。

### E. 属性推断攻击（Property/Attribute Inference）

目标：不判断具体某条样本，而是推断**整个训练集**的宏观属性——如训练数据中某人口统计学群体的占比、是否包含某类敏感数据、数据来源的分布特征。

- 方法：训练一批影子模型，分别用"具有目标属性"和"不具有目标属性"的数据集训练，观察两组影子模型在特定探测查询上的响应差异模式；再用该模式判别目标模型的响应落在哪一侧。
- 用途：评估模型是否泄露了训练数据整体的敏感统计特征（如"训练集是否主要来自某国用户"、"是否包含未脱敏的内部文档"），是隐私影响评估（DPIA 类工作）里的核心技法之一。

### F. 概率 / 排序 / 时间侧信道（Probability, Ranking & Timing Side-Channels）

侧信道的本质：接口返回或泄露了比"最终业务结果"更多的信息，这些多余信息可被单独武器化。

- **概率/置信度侧信道**：API 返回完整概率分布或 logprobs 时，即使业务上只需要 top-1 标签，这些分数也直接放大上面所有攻击（提取质量、成员推断置信度）的效果——是否暴露这一项本身就是一条高优先级检测项。
- **排序侧信道**：只返回 top-k 排序而不给分数时，排序变化对输入扰动的敏感度仍能反推决策边界形状，比纯 label-only 略强。
- **时间侧信道**：不同输入触发的计算路径不同（如提前退出的分类器、检索命中与未命中走不同代码路径、输入长度导致的处理时间差异）会在响应延迟上留下可观测差异。需要多次重复测量取统计量（均值/中位数/分布）以过滤网络抖动噪声，单次测量不可靠。
- **能量-延迟攻击（Energy-Latency / Sponge Attack）**：不以窃取信息为目的，而是构造能显著增加目标推理计算量/耗时/能耗的输入（如导致模型内部走最长计算路径、触发大量生成 token、命中最坏情况分支），用于评估可用性影响（拒绝服务倾向的隐私/资源层面变体）。这类技法本质上是资源消耗攻击，**评估其"是否达到实际影响"需格外谨慎，不得在未授权或生产环境上验证实际影响，仅在授权测试环境下小规模验证机制存在性**。

### G. 对抗样本 / 决策边界探测（Adversarial Examples & Decision Boundary Probing）

- **黑盒对抗样本生成**：无梯度访问时，用查询式方法（如基于有限差分估计梯度方向、或用代理模型白盒生成后做迁移）迭代扰动输入直至翻转预测，同时保持扰动幅度在人类不可感知/业务可接受范围内。
- **决策边界探测**：系统性地沿多个方向对种子样本做二分搜索式扰动，定位预测翻转的确切边界位置，用于刻画模型的鲁棒性边界形状（哪些方向脆弱、哪些方向稳健），也是成员推断 label-only 变体和对抗样本生成的共同基础设施。
- **与规避场景衔接**：若目标是绕过检测型分类器（如内容审核、恶意软件分类器）而非窃取信息，本节技法是规避载荷构造的底层方法，产出可直接喂给规避类 skill 使用。

### H. 技战法选择矩阵与查询编排

先按接口反馈强度选打法，避免无效消耗查询：

| 可观察反馈 | 首选打法 | 次选打法 | 核心度量 |
| --- | --- | --- | --- |
| 完整概率/logprobs | 软标签蒸馏、置信度成员推断 | 属性推断、边界探测 | agreement、KL/JS 距离、AUC |
| top-k 排序 | 排序扰动、主动学习提取 | 边界距离成员推断 | 排序翻转率、查询效率 |
| top-1 标签 | label-only 提取、迁移攻击 | 二分边界搜索 | agreement、最小扰动、queries/sample |
| 生成文本 | 前缀续写提取、多次采样分布 | 代理模型蒸馏 | 精确匹配率、n-gram 重合、独立来源比对 |
| 仅延迟/错误 | 重复测量的时间侧信道 | 输入复杂度探测 | 效应量、置信区间、方差 |

查询集按四类混合，而不是均匀随机撒点：

- **覆盖查询**：覆盖任务的主要类别、长度区间、语言和输入形态，建立全局功能近似。
- **边界查询**：围绕预测翻转点做局部搜索，提升代理模型对决策边界的拟合。
- **分歧查询**：当本地代理模型或多个影子模型意见不一致时优先询问目标，最大化单次查询的信息增益。
- **校准查询**：保留一组永不参与提取训练的固定样本，周期性复测目标是否版本漂移、温度变化或策略更新，避免把时序漂移误判为攻击效果。

成员推断和属性推断必须使用**嵌套评估**：调参样本、攻击训练样本、最终验证样本彼此分离；阈值只能在影子模型/训练集上确定，不能看过目标 ground truth 后再调阈值。除 AUC 外同时报告 TPR@低 FPR、置信区间和重复实验波动，避免仅凭总体准确率夸大效果。

### I. 组合打法

- **提取 → 迁移**：先获得代理模型，再在本地生成边界样本，最后只用少量目标查询验证迁移率；这是查询预算受限时最实用的组合。
- **成员筛选 → 数据提取**：先用成员推断给候选前缀排序，只对高分候选做续写提取，减少盲目枚举。
- **侧信道 → 架构假设 → 主动提取**：用延迟、错误和排序变化推断是否存在路由器、早退分支或检索层，再针对不同分支分别建立代理模型。
- **版本漂移差分**：固定校准集跨时间重放，识别目标升级前后输出边界变化；把模型版本变化与攻击算法收益分开计算。

## 工具

`blackbox_query_harness`：批量向目标查询接口发起结构化提示/输入，收集响应内容（标签/概率/logprobs，视目标暴露粒度而定）与响应时延，用于支撑上述 A-G 各类技法的查询-响应数据采集与统计分析。**注意：本工具能跑起来、能拿到一批数据，绝大多数场景下仍需要 P4 授权靶场 + 相应算力（训练影子模型/代理模型、跑对抗样本优化、做统计显著性检验）才能把"数据"变成"验证过的发现"** ——课时/环境限制下多数学员只能完成到"确认接口暴露粒度、跑通小规模查询采集"这一步，不代表攻击已完整验证。

## 验证标准

**能力宣传 ≠ 攻击成功**，必须区分层级，且每一层都要有可复核证据，不能用"理论上可行"替代：

1. **接口探测成立**：确认了目标返回的信息粒度（概率/logprobs/排序/仅标签）、是否存在可观测的时延差异——这是前提判断，不是攻击结果本身。
2. **数据采集完成**：跑通了批量查询、拿到了统计意义上足够的查询-响应样本量（模型提取/影子模型训练通常需要远超"跑了几十条"的规模，具体量级取决于任务复杂度，需在报告中给出实际查询数而非笼统称"已采集"）。
3. **统计显著性达标**：
   - 模型提取：代理模型在留出测试集上的功能一致率（agreement rate）达到预设阈值，且给出具体数字，不是"看起来很像"。
   - 成员推断/属性推断：攻击的 AUC/准确率显著高于随机猜测基线（0.5），并说明影子模型训练数据与目标训练分布的相似程度（相似度越低，结论越不可靠）。
   - 训练数据提取：吐出的内容能独立比对到已知真实数据源，比对方法和比对结果需明确写出。
4. **真实影响已验证**：仅第 3 层数字达标还不够，需说明这一发现对目标系统的实际隐私/安全影响（如提取出的代理模型确实能被用于生成有效规避载荷、成员推断结果确实吻合已知的 ground truth 训练集成员关系）。

未达到第 4 层的一律标注为"候选发现/待验证"，禁止在报告中直接称"已确认模型窃取成功"或"已确认存在成员推断漏洞"。**绝大多数本 skill 覆盖的技法（尤其模型提取、训练数据提取、能量-延迟攻击）必须在 P4 授权靶场配合足够算力（影子模型训练、大批量查询、对抗优化）下才能真正走到第 3/4 层**；课程级/低算力环境下大概率只能停在第 1/2 层，必须如实说明这一限制，不得夸大到"已验证"。

## 常见失败与规避

- **把"接口返回了概率"直接当成"模型已被窃取"**：规避——概率暴露只是提高了提取上限，实际提取质量取决于查询预算与代理模型训练是否真的收敛，需给出功能一致率数字。
- **影子模型训练数据与目标分布差异过大导致成员推断/属性推断失真**：规避——尽量用已知与目标同源或高度相似分布的数据训练影子模型，并在报告中明确标注分布匹配程度对结论置信度的影响。
- **把 LLM 幻觉误判为训练数据提取成功**：规避——任何"疑似记忆"输出都必须独立比对到可验证的真实数据源，无法比对时只能标注"疑似记忆，未验证"。
- **时延测量被网络抖动/并发负载污染导致侧信道判断失误**：规避——多次重复测量取统计量，控制并发和网络条件一致，报告中给出测量次数和方差而非单次读数。
- **在无授权或生产环境验证能量-延迟攻击的实际影响**：规避——这类技法本身即制造资源消耗，未授权环境下测试等同于对生产系统发起真实资源攻击，必须严格限定在 P4 授权靶场小规模验证，不得扩大到验证"实际造成多大影响"。
- **查询预算不足时仍套用满粒度场景的技法**：规避——先诚实判断预算/粒度上限，降级到对应变体（如 label-only 版本），而不是用不匹配的方法硬跑出低质量结果冒充高保真发现。

## 证据与报告

上报每一项发现需附带：
- 目标接口的访问方式与授权范围（P4 靶场标识、查询配额、测试时间窗口）。
- 侦察阶段确认的输出粒度（概率/logprobs/排序/仅标签）与时延可观测性，作为可行性上限的依据。
- 实际发出的查询数量、采集到的响应样本规模（不得笼统称"大量"，需给出具体数字或数量级）。
- 具体技法路径（模型提取/训练数据提取/成员推断/属性推断/侧信道/对抗样本）及为何选择该路径而非其他。
- 统计结果与阈值对比（功能一致率、AUC、准确率等具体数字），以及影子模型/代理模型的训练数据来源与分布匹配说明。
- 是否完成真实影响验证（ground truth 比对结果、或明确标注"未独立验证，仅统计层面显著"）。
- 使用 `blackbox_query_harness` 或其他工具时的运行环境（是否 P4 授权靶场、算力规模），便于复现与追溯升级路径。
