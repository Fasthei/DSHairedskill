# 方法资料结构（METHOD-01）

本文件定义 `entries/` 下每条方法资料必须包含的字段，供模型在判断和组合方法时按需检索使用。资料本身不是可执行脚本，也不是固定攻击清单——模型仍需结合具体项目的范围、材料和观察自行判断是否适用、如何组合。

## 字段

每条资料是一个独立 Markdown 文件（`entries/<slug>.md`），使用以下顺序的字段：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| 标题 | 方法的简短名称 | 一级标题 `#` |
| 适用组件 | 该方法面向的系统组件类型（如：对话型 Agent、RAG 检索层、工具调用层、模型服务本身） | 描述组件类型，不写死具体产品名；具体项目的目标由 `project` 插件的 `scope` 记录 |
| 需要的已有信息 | 使用该方法前，模型/测试者需要已经掌握的信息 | 明确列出，缺失时应先补充材料而非直接执行 |
| 可观察线索 | 判断该方法是否适用/是否命中的可观察现象 | 描述现象本身，不是执行步骤 |
| 前置条件 | 环境或访问层面的前提（如需要能直接与目标交互、需要能读取响应内容） | 前置条件不满足时应记为方法不适用，而非当作失败发现 |
| 验证标准 | 达到什么程度可以认为该方法的判断成立 | 区分“工具/请求执行成功”与“判断得到验证”；已验证结论需要证据支持（证据的存储与格式归 evidence-report） |
| 常见失败原因 | 该方法容易被误判或失效的原因 | 帮助模型排除假阳性/假阴性 |
| 原文位置 | 该资料提炼自的知识库位置 | 格式 `OSAI/课时N`；仅作开发参考索引，不代表运行时依赖，不复制课程原文 |

## 边界

- 资料条目描述“方法的判断结构”，不是分步操作教程或课程原文摘抄。
- 不以课程小节数量决定条目数量或插件数量；条目按“方法能解决什么判断问题”组织。
- 条目不假定固定的目标产品名、IP、账号或凭据；具体项目上下文由 `packages/project` 的清单记录。
- 一个条目命中不代表结论已验证——是否已验证、证据引用归 evidence-report 的发现状态管理。
