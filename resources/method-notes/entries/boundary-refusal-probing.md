# 边界探测：区分“拒绝”与“真否定”

## 适用组件

对话型 Agent（直接暴露用户交互界面的组件），尤其是配置了话题/能力限制的客服、内部工具类 Agent。

## 需要的已有信息

- 该 Agent 对外声称或被观察到的能力边界（例如“不讨论 X”“无权限访问 Y”）。
- 至少一种可以直接与该 Agent 交互并获取文本响应的方式（属于本项目的执行能力，不在本条目内规定）。

## 可观察线索

- 面对超出声明边界的提问时，响应内容属于以下哪一类：
  - **拒绝型**：明确表示“不能/不允许分享”，但话术本身暗示相关能力或信息确实存在（例如提及具体工具名、具体权限名）。
  - **真否定型**：表示“没有相关信息/能力”，不确认也不否认具体细节的存在。
- 对同一边界用不同措辞多次提问，响应是否保持一致；不一致本身也是一条线索。

## 前置条件

- 能够直接与目标 Agent 交互并完整读取其文本响应；离线的静态文档分析不适用本方法。
- 已知或怀疑存在某种能力/权限边界，否则无从探测。

## 验证标准

- “该边界确实存在且被拒绝话术间接确认”这一判断，需要至少一次可复现的拒绝型响应作为证据，且响应内容中包含具体到能被视为确认的细节（而不仅是模糊的“我不能帮你”）。
- 单次响应命中拒绝型话术只构成待验证观察；是否列为已验证发现、证据如何引用，由 evidence-report 的发现状态流程决定，本方法本身不产生“已验证”结论。

## 常见失败原因

- 把泛化的礼貌性拒绝（如客服话术模板中的通用免责声明）误判为能力确认。
- 未做多次/多种措辞复测，把一次性的模型幻觉或不稳定输出当作稳定边界。
- 忽略系统提示或护栏配置可能针对不同措辞有不同反应，导致结论只在特定问法下成立却被当作普适结论。
