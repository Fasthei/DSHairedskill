# 矛盾测试：诱导模型自我纠正以确认底层身份

## 适用组件

模型服务本身（对话型 Agent 背后实际调用的底层 LLM），尤其是部署方通过系统提示或话术要求模型隐藏/冒充身份的场景。

## 需要的已有信息

- 目标已声称或被要求呈现的身份（例如自称某自研助手名称）。
- 是否已有其他被动侦察线索（配置、文档、接口特征等）指向可能的真实模型family；矛盾测试用于交叉验证，不替代这些线索。

## 可观察线索

- 对模型的身份/来源做出**错误断言**（例如称呼一个错误的开发方或模型名）后，响应是否主动纠正这一错误断言，并在纠正过程中透露真实身份相关信息。
- 同一模型对不同错误断言的纠正倾向是否一致；不同措辞下结果不一致本身也是线索。
- 纠正行为的可靠性可能随模型规模/能力不同而不同，需要多次尝试建立置信度，而非单次断言即下结论。

## 前置条件

- 能够直接与目标模型服务交互并获取完整文本响应。
- 已知模型具备一定的“事实纠错”倾向前提假设可能不成立（小型/低能力模型可能不纠正也不确认，即模棱两可），需要结合其他方法交叉验证。

## 验证标准

- “底层模型确为某 family”这一判断需要多次矛盾测试在不同断言下得到一致的纠正内容，且纠正内容包含具体到可归属特定模型 family 的细节，而不是泛泛的否认。
- 单次响应不构成已验证判断；应作为观察记录并在多次交叉验证后再提出更高置信度的假设，已验证发现的证据链归 evidence-report 管理，本方法不直接产出“已验证”状态。

## 常见失败原因

- 小型/能力较弱的模型可能接受错误的身份声明而不纠正，被误判为“身份声明为真”，实际只是模型缺乏纠错能力。
- 只做一次矛盾测试就下结论，未与其他指纹识别线索（如接口特征、响应风格）交叉验证。
- 部署方可能针对已知的矛盾测试话术专门加了护栏，导致纠正行为消失，被误判为“身份确认失败”而非“方法被针对性拦截”。
